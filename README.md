## 1. 项目概述

《一墙之隔》是一款基于 Godot 4 引擎开发的 3D 非对称 1v1 追逃游戏。整张地图是一座被高墙切分的迷宫竞技场，双方共用同一套移动、拾取与投掷系统，只靠「走廊与墙」拉开距离：

- **追捕者**：贴身碰撞即可造成伤害，投掷物干扰，主动技能「幽灵状态」可以短时间穿墙截断逃跑路线。
- **逃生者**：只有 2 点生命，靠墙体绕行、投掷物干扰和「泡泡护盾」的击退效果活到比赛结束。

### 1.1 核心规则


| 项目       | 设定                                                 |
| ---------- | ---------------------------------------------------- |
| 对局人数   | 1v1（单人模式为玩家 vs AI，局域网模式为两名玩家）    |
| 单局时长   | 40 秒（`GameManager.match_duration`）                |
| 开局准备   | 3 秒倒计时，哨声响起后解冻操作                       |
| 逃生者生命 | 2 点，受击后 2 秒无敌并短暂加速                      |
| 胜利条件   | 追捕者：将逃生者生命打至 0；逃生者：存活到倒计时结束 |
| 单人难度   | 简单 / 普通 / 困难，仅影响 AI 躲避投掷物的概率       |

### 1.2 主要玩法循环

- 地图上随机刷新 8~12 件道具（石头 / 南瓜），走近自动拾取；
- 转动鼠标进行水平瞄准，滚轮调整仰角，屏幕显示抛物线轨迹，点击鼠标左键掷出；
- 石头命中会把对手砸倒击晕，南瓜命中造成减速并在地面留下一滩粘液；
- 追捕者用墙体绕行与穿墙技能逼近，逃生者用护盾击退与走位周旋，直到时间耗尽或生命归零。

### 1.3 双方基础数值对比


| 项目     | 追捕者                                                     | 逃生者                                                     |
| -------- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 步行速度 | 3.0 m/s                                                    | 2.4 m/s                                                    |
| 奔跑速度 | 6.0 m/s                                                    | 4.8 m/s                                                    |
| 跳跃初速 | 4.2 m/s                                                    | 4.2 m/s                                                    |
| 生命值   | 无生命值，不会被击败                                       | 2 点                                                       |
| 受击反馈 | 只会被石头击倒（无掉血机制）                               | 受击后 2 秒无敌 + 2 秒 1.4 倍移速                          |
| 伤害手段 | HitBox 接触即造成 1 点伤害（联机由主机统一结算，2 秒冷却） | 依赖投掷道具：石头击晕 / 南瓜减速                          |
| 主动技能 | 幽灵状态：持续 3 秒、冷却 10 秒，可穿墙并免疫投掷物        | 泡泡护盾：持续 0.5 秒、冷却 8 秒，挡下一次伤害并击退 10 米 |
| 攀爬能力 | 1.5 米以内矮墙可自动翻越                                   | 同左                                                       |
| 单局目标 | 40 秒内打空逃生者生命                                      | 存活 40 秒                                                 |

追捕者移动更快、逃生者更灵活，靠墙体与道具弥补速度差，构成非对称对抗的基础。

除正式对局外，项目还包含新手教程（拾取 → 投掷石头 → 投掷南瓜 → 躲避减速区 → 使用技能，追捕者教程额外包含穿墙环节）、角色技能介绍页、难度选择、局域网大厅与结算弹窗等完整流程。

### 2.1 技能说明

- **幽灵状态（追捕者，F）**：持续 3 秒、冷却 10 秒。期间只移除墙体碰撞层，模型渐变为幽灵形态并前倾漂浮；可穿墙移动，且投掷物会直接穿过身体。再次按 F 可提前结束，穿墙后离开墙体一定距离会自动结束。
- **泡泡护盾（逃生者，F）**：持续 0.5 秒、冷却 8 秒。期间免疫一次追捕者伤害，触发时沿水平方向把追捕者击退 10 米；未被打到则护盾自然消失。

## 3. 核心技术亮点与实现

### 3.1 网络联机系统（Host-Client 架构）

局域网联机由 Autoload `NetworkManager`（`scripts/network_manager.gd`）实现，采用 Godot 高层多人 API + ENet：主机 `create_server(7777, 1)`，客户端输入主机 IP 后 `create_client(ip, 7777)`，房间固定 2 人（1 主机 + 1 客户端）。大厅界面直接显示本机局域网 IPv4（优先 192.168 / 10 / 172 网段）与端口，供对方手动填写，属于「IP 直连」而非自动广播发现。

### 3.2 AI 行为逻辑

AI 与玩家共用同一套移动与动画代码（`CharacterBase`），只是控制源不同，因此手感一致。核心由四个模块组成：


| 模块 | 文件                           | 职责                                                 |
| ---- | ------------------------------ | ---------------------------------------------------- |
| HWAF | `hunter_wall_avoid_follow.gd`  | 追捕者绕墙跟随（NavigationAgent3D + 卡死复位）       |
| HPI  | 同上（子模块）                 | 预判拦截：把导航目标换成逃生者未来路径上的可拦截点   |
| HSA  | 同上（子模块）                 | 护盾规避：逃生者开盾时保持安全距离并切向绕行         |
| SWAE | `survivor_wall_avoid_evade.gd` | 逃生者绕墙逃离（环形采样选「最远 + 可达 + 开阔」点） |

- **HPI 预判拦截**：沿逃生者未来 1 秒的路径采样 8 个点，映射到导航网格后，分别计算「逃生者到达时间」与「追捕者沿导航路径到达时间」，优先选择能赶在对方之前到达的拦截点；逃生者即将撞墙转弯时，优先取转角之后的点，从而自然切出斜线抄近路。若当前没有可拦截点，则回退追当前位置（可配置）。
- **HSA 护盾规避**：安全距离 = 护盾半径 + 2m 缓冲 + 刹车距离 `v²/(2a)`；在安全距离外的环带上采样 12 个点，按「离追捕者近、开阔度高、离逃生者远」评分选点，并带退出迟滞与目标防抖，避免在「冲 / 退」之间来回抖动。
- **卡死检测**：每 1 秒检测一次位移，低于 0.1m 记为卡住；连续 3 次则复位到最近导航点并进入 RECOVER。幽灵技能与护盾击退通过计数式 `suspend_hwaf()` / `resume_hwaf()` 挂起导航，避免两个系统同时驱动导致速度翻倍。
- **战术规避（躲避投掷物）**：投掷物自带半径 2m 的 `DodgeDetector`，每发只判定一次。目标按当前「响应触发几率」掷骰：常规 30%、被真实命中后进入高度警觉 70%、刚成功规避过则进入「破绽」0%；单人难度可直接覆盖为 0%（简单）/ 100%（困难）。规避动作用 Tween 直接改 `global_position`（侧向 2m、0.2 秒），不污染 velocity，并先做一次侧向射线防止躲进墙里。
- **AI 道具行为**：空手时在 6m 内寻找「视线可达、最近、可拾取」的道具并跑过去，进入 1.5m 才真正拾取（不做隔空拾取），追不到会临时拉黑该道具防止卡墙；手上有道具时在 10m 内、且投掷路径无墙遮挡的情况下出手，仰角通过低抛弹道公式 `tanθ = (v² - √(v⁴ - g(gd² + 2hv²))) / (gd)` 反解，并对玩家目标加入飞行时间提前量。
- **AI 逃生者技能**：追捕者进入 2.5m 且仍在逼近时自动开盾；受击加速期间优先播放 flee 动画，逃跑方向在「正背向」基础上每 1.2~2.4 秒随机一个 ±45° 偏角，避免一直沿固定斜线跑。

### 3.3 动画与手持交互

- **运行时合并动画库**：角色模型自带动画（idle / walk / run / jump / climb / defeat 等）按名字关键字自动匹配；抱物（carry_idle / walk / run）、投掷（throw_item）、起身（stun_getup）四套动画在运行时 duplicate 后合并进角色自己的 AnimationPlayer，保证所有角色共用同一套动画逻辑。
- **动画方法轨驱动脱手**：`throw_item` 动画第 15 帧带有 `release_item` 的 Method Track。`_get_throw_release_time()` 直接读取方法轨时间点，用它把投掷动作拆成「前摇慢、收招快」两段倍率（2.9167 / 2.083），既保证动作有力量感，又不会让操作变钝；若动画被受击打断导致方法轨没触发，计时结束会兜底调用 `release_item()`，避免道具卡在手上。
- **道具挂载在双手中点**：拾取时道具被 freeze 成 `FREEZE_MODE_KINEMATIC`、碰撞层清零，并从场景 reparent 到 `HandAttachment`；随后每帧由 `CharacterBase._sync_item_to_hands()` 采样骨骼 `L_Hand` / `R_Hand` 的世界坐标，取两者中点作为旋转支点，并根据道具包围盒半高反推原点偏移（道具原点在底部）。
- **旋转跟随而非直接复制**：手骨的绝对朝向带有骨骼自身的 roll 基准，直接赋给道具会让石头 / 南瓜歪掉。这里在拾取后延迟 0.35s（等抱物动画混合稳定）采样一次手骨旋转作为基准，之后只让道具跟随「相对基准的旋转增量」——抱物待机时保持正立，挥臂投掷时道具随手臂一起翻转。
- **抱物站立定格**：抱物待机时播放 `carry_walk` 并把 `speed_scale` 置 0，避免角色站着还在迈步；奔跑 / 行走则按实际速度动态调整动画倍率。

### 3.4 投掷物理与轨迹预览

- **抛物线模拟 + 逐段射线**：`CharacterBase._update_trajectory_preview()` 按当前仰角与初速（18 m/s）逐帧积分出抛物线，每 0.05s 一段做 `intersect_ray`，命中即截断；命中角色时整条轨迹变红，命中地面时显示落点圆盘。
- **轨迹渲染**：`TrajectoryRenderer` 用 `MultiMeshInstance3D` 一次性绘制最多 64 个无光照小球，按 0.45m 最小间距抽稀，配合一个 `CylinderMesh` 落点圆盘，开销远低于逐个 `MeshInstance3D`。
- **出手速度直接赋值**：`apply_central_impulse` 要到下一个物理步才写入刚体，紧接着读 `linear_velocity` 仍是旧值，会导致联机广播的速度为 0。`ThrowableItem.launch()` 因此直接计算 `base_velocity + impulse / mass` 赋给 `linear_velocity`，同时叠加绕角色右轴反向的角速度（15 rad/s）实现空中前翻。
- **石头**：质量 2.0，命中角色 → `apply_stun()` 进入「倒地 → 起身」动画序列（保留碰撞层，倒地期间仍可继续掉血）；落地后靠速度衰减 + 物理休眠切到 DROPPED 状态，可再次拾取（避免在斜坡上永远等不到 sleeping 的卡死问题，速度低于 1 m/s 也会提前解锁）。
- **南瓜**：质量 1.5，命中角色 → `apply_slow()` 移速降至 55%、最多叠加 5 秒；撞墙不销毁，继续飞行直到落地才爆炸留滩。脱手后 0.2 秒内忽略与扔出者的碰撞，防止贴脸自爆。
- **手握道具与飞行状态机**：`ItemState { IDLE, THROWN, DROPPED }` 统一管理「能否拾取 / 是否结算命中」，飞行中关闭拾取检测，落地后重新开放，并有 0.25s 兜底补检解决「玩家一开始就站在范围内」时 `body_entered` 不重复触发的问题。

### 3.5 南瓜粘液滩与减速系统

- 粘液滩使用自定义空间着色器：36 张 splat 贴图随机选一张决定形状，再叠一层径向遮罩让边缘柔和淡出，`ALPHA = shape * mask * tint.a * opacity`，带自发光便于暗处辨认。
- 生成时向下射线贴地、对齐地面法线并随机绕法线旋转，然后 0.2 秒内由中心向外扩散（缩放 + alpha 渐显），6 秒后淡出销毁。
- 减速不是一次性 Debuff，而是「浸泡叠层」：粘液自带 `SlowArea`（半径 1.8m，覆盖角色高度 2m），站在里面每 0.2 秒叠一层、每层 1 秒、最多 5 层；腾空不叠层，所以 AI 站在粘液里会连续起跳减少层数。蛛网（`SlowZone`）复用同一套叠层接口，只是染色不同（粘液橙色 / 蛛网白色）。
- 视觉反馈：给模型挂一层 `material_overlay`，按剩余层数调整橙色不透明度与自发光；受击闪红的优先级高于减速染色。

### 3.6 技能系统（状态机实现）

`HunterGhostSkill` 与 `SurvivorBubbleShield` 都是 READY → ACTIVE → COOLDOWN 三态状态机，对外只暴露 `is_skill_ready()`、`get_skill_cooldown_ratio()` 等只读接口，HUD 只读不写。

- **幽灵状态**：只从 `collision_mask` 中移除墙体层（layer 1），地面与角色层保留；每帧用「上一帧位置 → 当前位置」的射线检测是否穿过薄墙，并用角色主碰撞形状 + 0.8m 安全球判断是否已离开墙体，避免卡在墙里结束。仍在墙内触发硬上限（10s）时复位到最近导航点。
- **幽灵模型替换**：运行时实例化 `hunter_skill.glb`，按 Head 骨骼高度等比缩放对齐头顶、绕脚部前倾 20°，再用 Tween 做双向透明度渐变（0.22s）完成模型切换。
- **泡泡护盾**：护盾期间拦截一次伤害并调用 `Hunter.apply_knockback()` 做水平方向物理击退（不瞬移、不穿墙）；消耗后保留 0.1s 宽限窗口，防止同一帧碰撞再次扣血。

### 3.7 全局架构与工程实践

- **单一数据源**：`GameManager` 统一管理比赛状态（MENU / CHARACTER_SELECT / COUNTDOWN / PLAYING / RESULT）、倒计时、血量与胜负，HUD 与结算只读取它，不各跑一套计时器；结算时 `get_tree().paused = true` 冻结玩家、AI 与物理，弹窗用 `PROCESS_MODE_ALWAYS` 保持可交互。
- **事件总线解耦**：`EventBus` 只广播「发生了什么」（拾取、脱手、假人命中、技能释放等），教程与 UI 订阅，避免引导逻辑散落在角色和道具脚本里。
- **音频系统**：`AudioManager` 用逻辑名映射音频文件，维护 8 个 2D + 24 个 3D 播放器池；脚步声按移动速度换算步频（走路约 1.9 步/秒、奔跑约 3.1 步/秒），落地音量按下落速度映射，3D 音源自带距离衰减与方位声像。部分音效（撞击闷响、规避风啸、警觉低吼）用代码合成 `AudioStreamWAV`。
- **导航烘焙**：`NavigationRegion3D` 运行时用 Recast 烘焙整张竞技场（agent 半径 0.75、cell 0.25），并把最低导航面归零对齐地面，解决「导航面高出地面 0.5m 导致路径点永远未到达」的问题。
- **手感细节**：`Shift` 短按锁定奔跑、贴墙正面强制行走防穿模、按水平距离判断路径点是否到达（跳跃时不会急停 / 倒退）、投掷前预热粘液着色器避免第一次爆炸卡顿。
- **物理引擎**：项目启用 Jolt Physics；碰撞层划分为 Wall(1) / Survivor(2) / Hunter(4) / Ground(8)。

## 4. 运行与演示说明

- **引擎版本**：Godot 4.x（工程 `config/features` 为 4.7，渲染后端 Forward+，物理引擎 Jolt Physics）。
- **源码运行**：
  1. 用 Godot 4.x 打开 `project.godot`；
  2. 等待首次资源导入完成；
  3. 按 `F5` 运行。主菜单可选择「单人模式」「局域网联机」或「新手教程」。
- **单人对局**：主菜单 → 单人模式 → 选择难度 → 选择角色 → 技能介绍页确认 → 开局。
- **局域网联机**：
  1. 双方进入「局域网联机」，填写昵称；
  2. 一方点击「创建房间」，把界面显示的本机 IP 与端口（默认 7777）告知对方；
  3. 对方填写 IP 后点击「加入房间」；
  4. 两人分别选择角色（同一角色不可重复选择），主机点击「开始游戏」。

若连接失败，请检查两台机器是否在同一网段，以及 Windows 防火墙是否放行该端口。

### 4.1 重新打包

`export_presets.cfg` 中已带一个名为「Windows Desktop」的导出预设，产物为 exe 加外置 `.pck`。发布时把这两个文件打成一个 zip（附件用 ASCII 名，例如 `wall-apart-v1.0-windows.zip`），作为 Release 的唯一附件上传；exe / pck 不再单独上传，也不要把二进制提交进仓库——`.gitignore` 已忽略导出目录。

- **试玩包下载**：[Releases → v1.0](https://github.com/kidd-sufring/wall-apart/releases/tag/v1.0)

## 5. AI 使用声明

### 5.1 引言

《一墙之隔》在开发周期内采用「AI Agent + 本地 MCP 工具链」的辅助开发模式：大语言模型承担概念设计、代码生成、工具调用（Function Calling）与自动化验证，人类开发者负责拆解需求、设定约束与验收。本文只说明 AI 的使用范围、使用方式与局限，具体技术实现见第 1–3 章。

### 5.2 AI 工具矩阵


| 环节       | 工具与用途                                                                           |
| ---------- | ------------------------------------------------------------------------------------ |
| 概念图     | Seedream 5.0 flash：以文本提示生成人物与地图概念图，先定住视觉基调                   |
| UI 控件    | Holopix AI：生成按钮、面板、血条、图标等控件素材，替代逐一绘制                       |
| 3D 模型    | Tripo 3D：按概念图生成并导出游戏就绪模型                                             |
| 骨骼动画   | Blender MCP：用自然语言驱动本地 Blender 调整动作，GLB 回传 Godot                     |
| 代码与逻辑 | Trae（IDE / SOLO 模式）、DeepSeek Harness：代码生成、跨文件重构                      |
| 调试与验证 | Godot MCP（`addons/godot_mcp`）与 `MCPRuntimeProbe`：headless 探针按真实输入流程走查 |

### 5.3 反思与局限

**收益**：概念图到模型的链路、样板代码（角色基类、UI 布局、Tween 动效）、API 记忆、抛物线弹道与低抛仰角反解等推导、Blender 批量关键帧插入，省去了大量查文档与重复劳动；运行时探针还把「改完再手动点一遍」变成可重复的回归检查。

**局限**：AI 产出常有「看起来对」的假象，典型问题均由人工 Review 与实机手感测试兜住——仅清零手骨旋转仍会折腕、硬掰手臂导致手掌悬空、`PanelContainer` 下用 `offset_transform` 硬偏移导致按钮命中区域错位且点击无响应、教程中技能可提前释放导致步骤卡死、飞行中忘记禁用拾取判定等。

**分工**：人类开发者充当「主程」，负责拆需求、写约束、Review 与打补丁，AI 承担实现与重复劳动。
